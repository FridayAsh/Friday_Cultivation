# 阶段 12：降境界加成失效与凡人灵气护盾修复

## 1. 问题与根因

- 渡劫固定快照的账本判定本身按 `RealmTopology` 计算，但普通突破生命/灵气加成只保存在两个全局累计字段中，`RealmTransition` 降境界时没有目标境界信息，因此旧的永久加成继续进入生命属性和最大灵气计算。
- 凡人 `getCurrentQi()` 已返回 0，但 `getMaxQi()` 仍会从凡人基础值和旧加成计算出非零灵气池；该状态会让灵气护盾链路拥有不应存在的防御入口。
- 旧版本曾把天骄生命奖励写入 `xiaoxiang.tribulation.hpMult` 的 `MULTIPLY_TOTAL` 属性修饰符；仅更新账本并不能删除玩家 NBT 中已经持久化的旧修饰符。
- 固定快照版本 1 只保存目标境界，没有保存目标子阶段。实际测试档处于“炼虚初期”时，“炼虚中期”的 1314 点快照仍被错误计入；这才是本轮持续复现的直接原因。

## 2. 修复契约

- 普通突破累计值新增 `breakthroughBonusTargetRealm` 和 `breakthroughBonusTargetSubStage` 完整目标进度快照。
- 当前境界或同境界子阶段低于目标时，普通突破生命/灵气加成返回 0；快照原始值仍保留，重新达到完整目标进度后恢复。
- `getMaxQi()` 对凡人境界在所有加成计算前直接返回 0，并将玩家灵气护盾入口显式排除凡人。
- `TechniqueEffectHandler` 在每 tick 和立即刷新入口统一删除旧 `hpMult` 修饰符，再只投影当前有效的固定快照。
- 固定快照升级为版本 2，新增 `targetSubStageId`；激活条件统一改为比较 `RealmTopology` 的完整境界+子阶段进度。
- 版本 1 快照从 `rewardKey` 迁移目标子阶段，现有测试存档无需删除快照或重开档。
- v3 普通突破数据缺少目标子阶段时，结合当前进度和同境界渡劫 `rewardKey` 恢复最高已知目标；这会正确迁移实际测试档的“炼虚中期→炼虚初期”数据。
- 境界令牌、境界选择、属性编辑器、渡劫失败、散仙选择和灵魂死亡降级入口全部立即刷新生命修饰符。
- 旧 NBT 没有目标境界字段时：非凡人档绑定当前境界；凡人档直接清理旧突破生命/灵气累计值，防止旧永久加成复活。

## 3. 验证

- 新增 `RealmTransitionTest.demotionToMortalDisablesTribulationAndOrdinaryBreakthroughBonuses`：验证令牌降到凡人后普通突破加成、渡劫快照和灵气池全部失效，并验证回到目标境界后快照恢复。
- 新增 `CultivationDataPersistenceTest.legacyMortalDataCannotRevivePermanentBreakthroughBonus`：验证旧存档凡人数据不会恢复永久突破加成。
- 新增“炼虚中期快照降到炼虚初期必须失效”回归测试，并覆盖版本 1 快照迁移与实际 MAX_HEALTH 修饰符删除。
- 新增同一境界子阶段下降时普通突破生命/灵气奖励同步失效、回升恢复测试。
- `gradlew.bat test`：BUILD SUCCESSFUL，32/32 测试通过。

## 4. 实际测试存档证据

读取 PCL 最新测试世界的玩家 NBT（只读，未改存档）得到：

- 当前进度：炼虚期初期；
- 渡劫账本固定生命奖励：筑基 188、金丹 320、元婴 522、炼虚中期 1314；
- 玩家 `xiaoxiang_tribulation_hp_snapshot` 修饰符实际为 2344，恰好是四条全部相加；
- 正确结果应只启用前三条，共 1030，炼虚中期的 1314 必须在炼虚初期停用。

该证据排除了“只是客户端显示延迟”和“只剩旧 hpMult UUID”的判断，直接证明版本 1 快照缺失目标子阶段是持续复现的主因。
