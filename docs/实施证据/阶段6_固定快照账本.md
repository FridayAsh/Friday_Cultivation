# 阶段 6：固定快照渡劫奖励账本证据

## 1. 执行范围

- 目标 Module：`cultivation/TribulationBonusSnapshot` 与 `CultivationData` 奖励账本
- 实施分支：`tribulation-rework`
- 基线：阶段 5 工作区

## 2. 固定快照规则

渡劫成功前先读取权威属性，再计算并固定：

- 最大生命 `healthBonus`；
- 最大灵气 `maxQiBonus`；
- 体质、筋骨、身法、法伤、气海固定点数。

快照记录目标境界稳定 ID 和 `rewardKey`。同一里程碑写入时覆盖旧记录；境界低于目标时快照停用，重新达到目标时自动恢复。

应用层已统一：

- 生命只由 `TechniqueEffectHandler` 的单一 `MAX_HEALTH ADDITION` 应用；
- 最大灵气只由 `CultivationData.getMaxQi()` 加固定值；
- 五维只由 `ZhenyuanBonusHelper` 查询层加固定点数；
- 删除旧 `List<double[]>`、ordinal 阈值和复利乘数应用。

## 3. 旧存档迁移

旧 `tribulationBonus` 首次加载时按 `legacy:<index>` 生成固定快照，后续只写 `tribulationBonusLedger`，保证迁移幂等且不再写旧列表。

## 4. 回归覆盖

- `100 × 50% = 50` 固定生命值示例；
- 境界下降停用、回升恢复；
- 同一里程碑替换而非叠加；
- NBT、Clone、Session 清理回归。

## 5. 尚未完成
